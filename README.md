# 中文会议论文摘要集

基于 LaTeX 的学术会议论文集自动生成系统。从 Excel 摘要数据生成格式化的 PDF 论文集，包含超链接目录、作者单位自动编号、通讯作者标记等功能。

## 项目结构

```
.
├── main.tex                          # 单篇论文示例模板
├── main_full.tex                     # 完整论文集主模板
├── generate_tex.js                   # Excel 数据处理与 LaTeX 生成脚本
├── toc_content.tex                   # 生成的目录文件（自动生成）
├── papers_content.tex                # 生成的论文正文文件（自动生成）
├── unit_report.csv                   # 单位/地区/邮编问题审计报告（自动生成）
├── region_map.csv                    # 地区名映射表（可选，人工维护）
├── zip_map.csv                       # 人工邮编对照表（可选，人工维护）
├── 摘要信息.xls                       # 原始论文摘要数据
└── .gitignore
```

> **重要**：`papers_content.tex`、`toc_content.tex`、`unit_report.csv` 都是**生成物**，
> 每次运行脚本都会被整份覆盖。要补充或修正数据，请改 `摘要信息.xls`、
> `region_map.csv` 或 `zip_map.csv`，**不要直接编辑生成物**。

## 依赖环境

- **Node.js** — 运行数据处理脚本，需要 `xlsx` 包
- **pdfLaTeX** — 需要支持 CJK（中文）编译，推荐 TeX Live 完整发行版
- **LaTeX 宏包**: `ctexart`、`newtxtext`、`newtxmath`、`hyperref`、`fancyhdr`、`geometry`、`longtable`、`setspace`、`indentfirst`

安装 Node.js 依赖：

```bash
npm install xlsx
```

## 构建流程

### 1. 生成 LaTeX 内容

从 Excel 数据生成论文正文和目录：

```bash
node generate_tex.js
```

此命令读取 `摘要信息.xls`，自动处理以下逻辑：

- 按**位置**配对作者单位 / 地区 / 邮编（三个平行列表按索引一一对应）
- 拆分并去重作者单位，按首次出现顺序编号
- 缺失邮编的全表反查补齐（A 级唯一映射自动补，B/C 级留空）
- 套用 `region_map.csv`（地区名规范化）与 `zip_map.csv`（人工指定邮编）
- 通讯作者姓名后添加星号标记
- 每位作者姓名后标注对应单位序号（去重且升序）
- HTML 实体和特殊字符转义为 LaTeX 命令
- 输出 `unit_report.csv` 审计报告

> 若输出文件正被 Excel / WPS 打开，脚本会提示 `无法写入 xxx —— 该文件正被其他程序占用`。
> 关闭它后重新运行即可。

### 2. 编译完整论文集

需要两次编译以更新交叉引用和目录页码：

```bash
pdflatex main_full
pdflatex main_full
```

输出文件：`main_full.pdf`

### 3. 单篇测试编译（可选）

用于验证模板样式：

```bash
pdflatex main
pdflatex main
```

输出文件：`main.pdf`

## 数据格式

Excel 文件（`摘要信息.xls`）应包含以下列：

| 列名 | 说明 |
|------|------|
| 论文专题 | 论文所属专题分类 |
| 论文编号 | 论文唯一编号 |
| 论文标题 | 论文题目 |
| 作者姓名1-12 | 作者姓名（最多12位） |
| 作者单位1-12 | 作者对应单位，**半角逗号分隔的列表** |
| 作者单位地区1-12 | 与 `作者单位1-12` **按位置一一对应**的地区，半角逗号分隔 |
| 作者单位邮编1-12 | 与 `作者单位1-12` **按位置一一对应**的邮编，半角逗号分隔 |
| 通讯作者姓名 | 通讯作者姓名 |
| 通讯作者Email | 通讯作者邮箱 |
| 摘要文本 | 论文摘要内容 |
| 论文关键字 | 论文关键词 |

> 三个平行列表按**索引位置**配对：`作者单位N` 的第 j 项 ↔ `作者单位地区N` 的第 j 项 ↔ `作者单位邮编N` 的第 j 项。
> 三列表长度不等时按位置配对（多余忽略、缺失留空）。
> 切分只认**半角逗号**；全角「，」出现在单位名内部（如“南京大学物理学院，南京大学声学研究所”），必须保留。

## 缺失邮编处理

源数据中约三成单位条目没有邮编（空串，或 `000000` 占位）。脚本按三级处理：

| 级别 | 判定 | 处理 |
|------|------|------|
| A 级 | 「单位名+地区」在全表只有**唯一**有效邮编 | **自动补齐**并记入报告 |
| B 级 | 「单位名+地区」对应**多个**不同邮编 | 留空，记入报告待人工确认 |
| C 级 | 全表找不到同「单位名+地区」的有效邮编 | 留空，记入报告 |

运行 `node generate_tex.js` 后生成 `unit_report.csv`（UTF-8 带 BOM，可直接用 Excel 打开），
按 `类型` 列筛选 `已补齐-A级` / `缺邮编-B级` / `缺邮编-C级` / `长度不一致` 即可定位所有问题条目。
A 级补齐发生在单位编号去重**之前**，因此同一单位的“无邮编条目”会自动与“有邮编条目”共用同一个编号。

## 地区名规范化（`region_map.csv`）

源表的 `作者单位地区N` 里混用了两种颗粒度：有的是「市」（`西安市`、`哈尔滨市`），
有的是「区」（`海淀区`、`闵行区`）。若希望统一成「市」，在 `region_map.csv` 里写两列即可：

```csv
原值,新值,说明
海淀区,北京市,北京市辖区
闵行区,上海市,上海市辖区（上海交通大学）
```

- `#` 开头的行是注释；文件不存在时不做任何映射。
- 映射**只作用于展示与单位去重**；邮编反查索引仍用原始地区名 —— 
  否则「单位+城市」的键会比「单位+区」粗，可能把唯一映射变成多候选（A 级降为 B 级）。
- 实测：映射后展示地区种类由 67 种降到 52 种，A 级自动补齐仍为 138 条（零回归）。

## 人工邮编对照表（`zip_map.csv`）

对于 B/C 级（脚本无法自动确定邮编）的条目，可直接在 `zip_map.csv` 里指定，**优先级最高**：

```csv
单位名,地区,邮编,级别,候选,出现论文
某大学 某学院,某市,123456,C,,G0001 G0002
某大学 某研究所,某市,654321,B,100001 / 100002,A0123
```

- 只需填前 3 列；**邮编列留空的行视为无效规则，会被忽略**（所以可以把待办清单留在文件里）。
- `地区` 列写**映射后的**地区名（与 `unit_report.csv` 的「地区」列一致）；留空表示「不限地区」。
- 命中后**直接套用**（无论原文有无邮编），并在报告里记为 `已指定-zip_map`。
- 运行时会报告**未被任何论文命中的规则**，便于发现单位名/地区名写法不一致。
- **海外/港澳条目**：若源表地区就是 `海外`（或已映射为 `香港`/`澳门`），把「邮编」留空即可，
  脚本会保持「有地区、无邮编」，不去猜一个邮编填上。

> **编码**：`region_map.csv` 与 `zip_map.csv` 既可以是 UTF-8（可带 BOM），也可以是
> GBK/GB18030（中文版 Excel「另存为 CSV」的默认编码）。脚本会自动识别，并在控制台提示
> `注：zip_map.csv 不是 UTF-8，已按 GB18030 …读取。`。

> 当前数据：322 条缺邮编条目去重后是 **105 个「单位+地区」组合**
> （15 个 B 级已给出候选邮编，90 个 C 级需自行查找）。只需填 105 行，比改 Excel 划算得多。
> 该表已填写完毕：**99 条有效规则全部命中**，另有 6 条海外/港澳条目按约定留空邮编。

## Unicode 上标 / 下标规范化

源表里的上标混用了三种写法，而且**中文 pdfLaTeX 会静默丢掉它们**：

| 源表写法 | 说明 |
|---|---|
| `min⁻&sup1;` | Unicode 上标减号 `⁻`（U+207B）+ 命名实体 `&sup1;` |
| `10⁻⁴` | 连续 Unicode 上标字符 |
| `10⁻4` | 上标减号 + **普通字号**数字（源表笔误） |
| `80 mW/cm&sup2;` | 命名实体 |
| `&#185;` / `&#xB9;` | 数字实体（即 `¹`） |

**为什么会被丢掉**：`pdfLaTeX` + CJK 字体没有 U+2070–U+209F 的字形，而 CJK 宏包遇到
缺字形时**直接丢弃且不报任何警告**——`main_full.log` 里连一条 `Missing character` 都没有。
结果是 `min⁻¹` 被排成 `min 1`、`10⁻⁴` 被排成 `10 ⁴`。

**处理方式**：新增 `supSubToMath()`，把 Unicode / 命名 / 数字上标统一切换到数学模式
`$^{…}$`（下标同理 `$_{…}$`），交由 `newtxmath` 排版，字形与减号都正确。
`convertHtmlEntities()` 的处理顺序也相应调整为：

1. **数字实体先解码**（`&#185;` → `¹`），否则解出的字符会绕过后续的字符类匹配；
2. 清掉零宽 / 不可见字符；
3. `supSubToMath()` 把上/下标串整体转成 `$^{…}$` / `$_{…}$`（此步必须在命名实体替换**之前**，
   才能把 `⁻` 和 `&sup1;` 合并成同一段 `⁻¹`）；
4. 替换其余命名实体（`&alpha;`、`&ordm;` 等）。

`&sup1;/&sup2;/&sup3;` 不再映射为 `\textsuperscript{N}`，统一走 `$^{N}$`，与其余单位风格一致。

**已知写法缺陷（`MERGE_SIGN_DIGIT`）**：C0317 的源表写成 `10⁻4`（上标减号 + 普通数字）。
脚本用 `MERGE_SIGN_DIGIT = true` 把它合并成正确的 `$^{-4}$`。更彻底的做法是把源表改成
`10⁻⁴`。该开关在 `generate_tex.js` 中，设为 `false` 则原样保留、渲染为 `10⁻4`。

**建议**：以后新增摘要请直接在源表写 `10⁻⁴`（连续 Unicode 上标）或 `10&sup1;`，
不要写 `10⁻4` 这种混合写法。

## 引号规范化（直引号 → 中文弯引号）

源表里的引号**一律是 ASCII 直引号 `"`**（例：A0463 的 `在"双碳"目标`）。

**为什么直引号会出错**：`newtxtext`（TeX Gyre Termes）把 `"` 实现成**按位置的 TeX 连字**——
开引号位置排 `“`、闭引号位置排 `”`。但在中文段落里两侧都是汉字，Termes 判断不出方向，
于是**每一个 `"` 都被排成右引号 `”`**，PDF 上出现 `在”双碳”目标`（开引号也是右引号）。

**处理方式**：新增 `normalizeDoubleQuotes()`，作为 `convertHtmlEntities()` 的最后一步（⑤）：

- 源表中 `"` 的数量**恒为偶数**（全库 51 个字段 / 158 个引号，已逐一核对），
  因此按「出现次序奇偶」交替判定开 / 闭即可；
- 同时**跟踪文本中已存在的 `“`/`”`**（D0384、V0235 等少数条目本来就是真弯引号），
  遇到时同步开 / 闭状态，避免混排时错位；
- 转换只作用于**双引号**。单引号 `'` 保持原样——`&rsquo;` → `'` 经 Termes 连字渲染成 `’`，
  用于英文所有格（如 `Breaker&rsquo;s Reef`）是正确的，不能按奇偶交替处理。

其余实体映射同步修正：`&ldquo;` → `“`、`&rdquo;` → `”`（此前错误地映射成直引号 `"`）。

**验证结果**：`papers_content.tex` 中直引号 `"` 由 158 个降为 **0 个**，
真弯引号由 6 对增至 **85 对**，逐行配对检查 0 处未闭合；
从 PDF 抽取文本复核为 `“` 87 个 / `”` 87 个 / 直引号 0 个。
`“`、`”` 均属 GB2312 常用标点，中文字体有字形，渲染正常。

**建议**：源表继续写直引号 `"` 即可（脚本自愈）；也可直接写 `“”`，两者都能正确处理。

## 摘要正文开头的冗余标签剥离

模板 `\printpaper` 会自行印出「摘要」二字（`main_full.tex` 第 153 行，注释写明“不加冒号”），
但源表里有多篇作者把「摘要：」也写进了正文，PDF 上就成了
`摘要　　摘要：为充分考虑椭圆换热管恒定的热耗率…`（重复一次）。

**处理方式**：新增 `stripAbstractLabel(text, rawTitle)`，作为 `sanitizeAbstract()` 的第零步，
循环（最多 6 轮）剥离开头以下三类内容：

1. `摘要：` / `摘 要：` / `摘    要：` / `摘要:`（半角冒号）/ `【摘要】` 标签；
2. **整行与论文标题完全相同**的行（D0043 的正文把标题重复了一遍）；
3. **单独一行只有「摘要」**（可带冒号）。

每轮同时去掉开头的空白、换行与**零宽字符**，直到不再变化为止。

**踩过的坑**：D0043 的「论文标题」以 **U+200B 零宽空格**开头（Excel 复制粘贴残留），
而 JS 的 `\s` 不匹配零宽字符，导致标题比对一直失败、剥不掉。
因此比对前两边都先经 `normalizeForCompare()` 去掉零宽字符
（ZWSP/ZWNJ/ZWJ/LRM/RLM/WJ/BOM）再比较。

**边界**：只处理**开头**。正文中间出现的「摘要」二字不会被误删
（例如「从宏观和摘要两个层面」）。

**验证结果**：432 篇中「摘要：」式开头由 **15 篇降为 0 篇**，
「摘要首行重复标题」由 **1 篇降为 0 篇**，「摘要首行是独立『摘要』行」**0 篇**。

## 数值与单位之间的空格收紧

源表在数值与单位之间写的是**普通 ASCII 空格**（`厚度仅20 mm`、`（50 m、200 m、500 m）`）。

**为什么会被拉宽**：TeX 里普通空格是**可拉伸的行间胶（interword glue）**。
中文段落两端对齐（justified）时没有被拉伸余地的地方少，这个空格就会被拉得很宽，
PDF 上出现 `厚度仅20    mm`、`（50   m、200   m、500   m）`。

**处理方式**：`sanitizeAbstract()` / `sanitizeTitle()` / `sanitizeKeywords()` 均调用
`tightenNumberUnit()`，删掉「数字 + 空格 + 单位」中的空格（`20 mm` → `20mm`）。

- 空格类：半角空格 / 制表符 / 不换行空格 / 细空格 / 窄不换行空格 / 全角空格 / TeX 的 `~`；
- 单位来自 **白名单**（长度、质量、时间、频率、声压级/声级、功率、电学、温度、`m/s`、`km/h` 等约 90 个），
  长单位排在前面（先匹配 `kHz` 再匹配 `Hz`），不会误改「3 A 级」这类非单位内容；
- 末尾的 `(?![A-Za-z])` 保证 `20 meters` 中的 `m` 不被误判成米。

**如需保留一个细空隙**：把 `generate_tex.js` 中的 `const UNIT_SPACE = ''` 改成 `'\\,'`
（`\thinspace`，1/6 em，**不可拉伸**），即符合 GB/T 3101 的「数值与单位间留细空隙」写法。

**验证结果**：全库 **265 处**数值+单位（`Hz` 40、`dB` 16、`kHz` 12、`m` 9…），
逐条核对**全部是真实量纲、0 处误判**；生成后 `papers_content.tex` 中残留 **0 处**。

## 基金 / 致谢句移至页脚（`extractFunding`）

源表里有 **4 篇**把基金致谢句写在了**摘要正文的末尾**，与正文混在一起：

| 论文编号 | 专题 | PDF 页码 | 基金句 |
| --- | --- | --- | --- |
| A0463 | A. 物理声学 | 48 | 本课题承蒙国家自然科学基金项目(12274122，12574480)的支持，特此致谢！ |
| A0464 | A. 物理声学 | 49 | 本论文承蒙国家自然科学基金项目(12574480，12274122)的支持，特此致谢！ |
| A0465 | A. 物理声学 | 50 | 本课题承蒙国家自然科学基金项目(12574480，12274122)的支持，特此致谢！ |
| E0461 | E. 检测声学 | 229 | 本论文承蒙国家自然科学基金项目(12274122，12574480)的支持，特此致谢！ |

全库其余 **428 篇**摘要正文中**没有**任何基金 / 致谢字样（`B0169`、`G0396`、`H0139` 命中的是
普通行文里的「课题」，`C0136` 命中的是一个电话号码 `18873621326`，均已排除）。

**处理方式**：`extractFunding()` 在 `processPaper()` 里先用 `FUND_HINT_RE` 粗筛
（`基金|资助|承蒙|致谢|感谢|重点研发计划|基金委`），命中后再**只在摘要末尾取最后一个句子**
（`SENT_END_RE` 按 `。！？；` 与换行切分），若「末句含基金词」且「剩余正文非空」才摘出，
避免把正文本体掏空。摘出的句子经 `sanitizeFunding()` 转义后作为 `\printpaper` 的**第 9 个参数**，
由模板印在**页脚**「基金项目：」一行，位置在 3cm 脚线之下、`通讯作者：` 之上。

```latex
\vfill
\noindent\rule{3cm}{0.5pt}\\[2pt]
\if\relax\detokenize{#9}\relax\else
  {\songti\wuhao 基金项目：#9}\\[2pt]
\fi
{\songti\wuhao 通讯作者：#6}
```

**验证结果**：432 篇中 **4 篇**页脚有基金行、**428 篇**为空（脚本做括号解析逐块核对，
`arity!=9: 0`、`fund-in-body: 0`、`fund-in-footer: 4`），人工抽查页 48 / 49 / 50 / 229 与
无基金的对照页 25 全部符合预期。

### 实现过程中撞到的两个 TeX 硬限制

1. **TeX 宏参数上限为 9 个**
   最初想再加一个 `labelId` 参数（`\newcommand{\printpaper}[10]`），直接报
   `! You already have nine parameters`；改用 LaTeX3 的
   `\NewDocumentCommand{\printpaper}{mmmmmmmmmm}` 同样报
   `! LaTeX cmd Error: Too many arguments`——**任何 LaTeX 方言都做不到 10 个参数**。
   解决：`labelId` 本就恒等于论文编号，直接删掉，超链接锚点改用**第 2 个参数**
   （`\hypertarget{paper:#2}`）。全库 432 条编号经校验均为纯字母数字
   （出现过的字符集：`V0467138295ABCDEGHIJKLMNOPQRSUW`），锚点与目录完全一致；
   `generate_tex.js` 里另加了一条 `console.warn` 守卫，将来若出现非字母数字编号会提前告警。

2. **花括号参数里的「空行」会被读成 `\par`**
   基金参数如果照抄其它参数的写法：
   ```latex
   {%

   }
   ```
   那一行空行就成了「空行」，TeX 把**空行读成 `\par`**，于是参数**并不是空串**而是 `\par`。
   `\if\relax\detokenize{#9}\relax` 的空值判断被绕过，模板就去排版
   `基金项目：\par` 再接 `\\[2pt]`，在空白行上换行 → 428 篇全部报
   `! LaTeX Error: There's no line here to end.`
   最小复现（`\detokenize` 打印实参）：多行「空」参数得到 `ARG9 = [\par ]`，
   而 `{}` 得到 `ARG9 = []`。
   **解决**：第 9 个参数**必须写成单行** `{${softenBreaks(funding)}}`，
   其余 428 篇的空值才是真正的 `{}`。`generate_tex.js`、`main_full.tex`、`main.tex`
   均已就地加注释，提醒后来者这个参数**不能**用多行 `{%` 写法。

## 排版特性

- 中文字号自定义命令（五号、小四、四号、三号、小二）
- 作者单位自动去重与编号
- 通讯作者星号上标标记
- 超链接目录，支持点状引导线
- 每篇论文独立页面，页脚显示通讯作者信息
- 页眉三分栏：左「2026年10月23-26日」、中「2026年全国声学大会」（字号略大）、右「中国·西安」
- 单位量纲的上/下标（`min⁻¹`、`°C⁻¹`、`10⁻⁴`、`m²`、`m³`）统一以数学模式排版
- 直双引号自动转为中文弯引号 `“”`，开 / 闭方向正确
- 摘要正文开头多余的「摘要：」标签、重复的标题行自动剥离（模板已自带「摘要」二字）
- 数值与单位之间的空格自动删除（`20 mm` → `20mm`），避免中文两端对齐把空隙拉宽
- 摘要末尾的基金 / 致谢句自动摘到**页脚**「基金项目：」一行（428 篇无基金者不打印该行）

## 已知问题

- **源表混用半角连字符与短横线**：如 V0307 中 `7-9月`（半角 `-`）与 `1500–1900`（`–` U+2013）。
  排版上不影响，如需统一请改源表。
- **正文（`\printpaper` 摘要）中允许 `“` 出现在行尾、`”` 出现在行首**（本模板未启用中文标点
  避头尾规则）。如需严格避头尾，可在 `main_full.tex` 中加载 `xeCJK`/`luatexja` 或手工加
  `\penalty10000` 控制。
